# Valheim terrain investigation — 16 October 2026

The playable Rust sandbox now loads a real 64 × 64 metre tile generated by the installed Valheim build. It replaces the previous sine-wave ground when the private terrain reference cache is present. Launch **Open Playable World.cmd**. This is the first terrain import slice, not a port of the whole world generator or a user's saved world.

## Verified pipeline

Installed build identity was rechecked using Open-Greyling.ps1 -CheckOnly: executable, Mono gameplay assembly, asset bundle and SoftRef manifest match the recorded build. Assembly MVID is `65d2b4f8-e94e-4805-8a80-1451498a82d7`. Generator version is 2.

1. `World(name, seedName)` derives `m_seed` using `StringExtensionMethods.GetStableHashCode`; its inspected constructor sets world-generation version 2.
2. `WorldGenerator.Initialize` creates the generator. Its constructor initializes Unity random state from the seed, derives offset/river/stream seeds, configures FastNoise, and pregenerates non-menu world data. A complete terrain port must reproduce these details and the installed biome/river rules.
3. `HeightmapBuilder.Build` uses `(width + 1)^2` vertices, tile origin `center - width * scale / 2`, corner biome-sector data, biome height evaluation and smoothing/interpolation. It produces base heights and paint-mask data. Sampling `WorldGenerator.GetHeight` alone is not a verified replacement for the tile builder, especially near biome boundaries.
4. `Heightmap.Generate` copies the base heights and paint mask, then applies terrain modifiers. `TerrainComp` persists edits separately. This slice has no saved terrain edits or generated locations/vegetation.
5. Installed `Heightmap.CalcVertex` and `RebuildCollisionMesh` define row-major vertices and triangles `(a,c,b), (b,c,d)` for each quad. Rust now reconstructs these exactly. Walking uses triangle-plane interpolation on the same diagonal; the former procedural mesh diagonal was replaced.

Evidence: `evidence/world-stage-001/HeightmapBuilder.il.txt`, `terrain-call-map.csv`, and the original baseline type IL. These are private installed-code evidence, not distributable project assets. Candidate original environment assets, including tree prefab paths and `Assets/Shaders/Heightmap.shader`, are recorded in `next-environment-assets.txt`; these candidates have not yet been imported.

## Native reference versus independent work

`diagnostic/TerrainCheck.cs` runs only in the marked, save-isolated test copy. It constructs a new in-memory reference world with seed name `LabTerrain1`, numeric seed **1121644293**, and selects a bounded Meadows tile above water. It invokes the actual installed tile builder. It also invokes the installed Heightmap collision-mesh method on an inactive test component and raycasts a dedicated native collider. It does not load the user's world or copy any of their save payloads.

Current private cache: `private-cache/terrain/native-20261016-131713-9638456`, selected by `native-current.txt`. Tile centre is **(-64, -64)** in original world coordinates, width 64, scale one metre. There are 4,225 height samples and 8,192 triangles. `tile.bin` SHA256 is `F4661B1726A2ABCFC6C2789DBF7876157C176BE9656EFC84F41A7342115F79CD`.

The cache's TER1 format stores width, spacing, original world centre, centre height, seed, generator version and little-endian Float32 heights. Rust parses it and independently reconstructs vertex coordinates, indices and triangle surface evaluation. **The generator has not been ported to Rust:** the source heights are obtained through Unity. They are not independently decoded from a saved world. The sandbox translates the tile centre to local X/Z zero and subtracts its centre height; it does not rescale terrain. Native reference comparisons use original unshifted heights.

World rendering now reflects Unity Z into OpenGL consistently, correcting camera handedness so D moves right. The terrain's green checker colouring, trees, piles and floor remain custom prototype visuals. No native terrain textures, biome shader blending, grass, water, locations or tree placement have been reproduced. No native terrain image/lighting parity is claimed. The original Greyling remains the independently decoded game asset already described in GREYLING_REPORT.md.

## Reproduce and continue

Build diagnostic with the existing SDK and run the existing patcher to deploy it to the separate copy, then run `Run-Terrain-Reference.ps1` with Steam available and no other Valheim process. The runner refuses to interrupt an existing session. Use `Build-Playable.ps1` and the sandbox's `--verify-terrain <native reference directory>`, `--scenario <new save path>`, `--verify-save <same path>` and `--playtest <new directory>` modes to repeat verification. No dependencies were added.

Sandbox save version 2 now binds its save to the terrain seed/version/centre. Older prototype saves are rejected with an explanation instead of silently applying them to different terrain. Existing files are not migrated or deleted; F5 retains the previous file as .bak. No original-save, mod or server compatibility is implied.
